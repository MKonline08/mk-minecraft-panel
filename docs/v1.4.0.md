# v1.4.0 — Files, worlds, backups and modpacks

## New controls

Files now supports selecting files and folders and moving them to trash. Stop Minecraft first. Trash is stored outside the live server folder, survives restarts, and has Restore and Empty trash controls. Root and panel metadata cannot be deleted. Restoring never overwrites an occupied path; move the conflicting file first. Trash does not expire automatically and counts toward disk usage.

The World tab inspects uploaded Java world ZIPs before confirmation. Choose the world when several are present. Imports respect custom level-name settings and include sibling Nether/End folders. A verified full-server backup precedes replacement, and Minecraft remains stopped.

Backups accepts MK backups and full Java server ZIPs. Upload only adds a backup; restore is separate. External backups must contain server.properties; world-only archives belong in World. Choose exact runtime versions when the archive has no MK runtime metadata.

Modpacks provides Modrinth browsing and uploaded .mrpack, CurseForge-export ZIP, and self-contained server-pack ZIP installation. New-server setup has a modpack option: create a stopped server, then browse/upload the pack. Manifest versions control Minecraft and loader selection. Generic archives require explicit runtime selection; installation scripts are never executed. Unsupported custom launch requirements must be supplied as a compatible server pack.

Existing servers default to a fresh pack installation. Keeping a world requires matching Minecraft versions and an explicit choice. Different mods may still make the world incompatible. Files are prepared separately; previous files and runtime settings are retained for Roll back import. After validating an installation, stop it and choose Keep this installation to discard that rollback copy before another import. Safety backups remain subject to retention.

Installed and Startup verified are distinct states. Startup verification checks container health and RCON; failures retain logs and allow rollback. No panel can guarantee arbitrary third-party mod combinations or client compatibility.

## Upload limits and downloads

Set IMPORT_UPLOAD_BYTES and IMPORT_EXPANDED_BYTES on the panel container to override the default 2 GiB upload and 8 GiB expanded limits. Archives are limited to 100,000 entries. Corrupt ZIPs, escaping paths, symlinks, encrypted archives, duplicate paths and checksum mismatches are rejected. Remote downloads use HTTPS, an explicit provider-host allowlist, bounded redirects, and public-address DNS validation at connection time.

Set CURSEFORGE_API_KEY on the panel container for CurseForge export resolution. It is never returned to the browser. Files unavailable for automatic download are listed with manual upload controls and verified against provider checksums. Client-only information in CurseForge exports is incomplete: use the author's server pack where available.

Persistent additions under /data: trash/<server-id>/, imports/<import-id>/, and staging/<server-id>-previous-<import-id>. Interrupted swaps block startup until recovery. A failed installation retained during rollback remains in staging for diagnosis. Keep adequate free space for uploaded archives, prepared files, old installation, and safety backup.

## Verification and upgrade

CI gates publication on build/audit, API and browser checks, the existing eight-server matrix, and three minimal real modpack fixtures. Fixtures pin FerriteCore Fabric 7.0.3 (Minecraft 1.21.1, loader 0.16.10), Forge 6.0.1 (Minecraft 1.20.1, Forge 47.3.0), and NeoForge 7.0.3 (Minecraft 1.21.1, NeoForge 21.1.80). These are small integration packs, not compatibility certification of large community packs. The checks exercise startup, RCON, restart, persistent worlds, backup/restore, and rollback. Quilt remains covered by the existing runtime matrix and import fixtures.

Package verification upgrades populated v1.2.1 and v1.3.0 installations. Confirm the actual GitHub Actions result for the release commit before updating.

Stop Minecraft and the panel; copy the full CasaOS data directory to separate storage. Once v1.4.0 is published, change the existing panel image to ghcr.io/mkonline08/mk-minecraft-panel:1.4.0. Preserve the existing host port, HOST_DATA_DIR and bind mount. Do not import a fresh Compose file over an existing installation. Existing accounts and servers remain registered, and unchanged servers retain their pinned runtime images.
