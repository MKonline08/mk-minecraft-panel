# v1.3.0 — backups and console

This release targets the existing Intel/AMD CasaOS installation. The panel's Minecraft image pins, server IDs, game ports and persistent data paths stay compatible with v1.2.1.

## Updating an installed app

1. Stop your Minecraft servers through the panel, then stop the panel in CasaOS.
2. Copy the complete host data directory to another disk. The default is `/DATA/AppData/mk-minecraft-panel`; include `panel.sqlite`, any SQLite WAL files, `servers`, `backups` and `images`.
3. After v1.3.0 is published, edit the **existing** CasaOS app and change its panel image to `ghcr.io/mkonline08/mk-minecraft-panel:1.3.0`. Keep the existing host port, volume source mounted at `/data`, and `HOST_DATA_DIR`. The latter must match that volume's host path.
4. Apply the image update and sign in with your existing account. Confirm the server list, worlds and backups, then start your servers.

Do not import a replacement app or remove app data to update. If you moved storage or changed the web port, keep those custom values. To roll back, stop the panel and servers and restore the saved data directory with the previous panel image.

Existing interval schedules retain their settings. Missing announcement settings default to enabled with 300, 60 and 10 second warnings. Normalizing records is additive; accounts, player history, worlds, property files and Minecraft images are not recreated. Existing backup archives remain downloadable and restorable and display **Verification unknown (older backup)** until verified as part of a restore. Restoring validates the archive but does not relabel an older archive as newly verified.

## Backup controls

Choose manual-only, interval, daily or weekly backups per server. Calendar schedules store an IANA timezone (initially your browser timezone). A repeated local time runs once at its first occurrence; a skipped time runs at the next valid local minute. If an operation occupies the server, its backup waits and runs once when available. Missed calendar occurrences while the panel was offline are coalesced into one due backup if its due time had been persisted. An existing interval schedule remains anchored to its last successful backup.

Announcements have editable warning, shutdown, completion and failure messages. Use `{server}`, `{remaining}` and `{duration}`. Scheduled warnings use configurable seconds; manual backups give ten seconds. Preview messages without sending, or use **Send test announcement** on a running server. Turning off announcements removes the manual delay. Changing backup settings cancels a queued countdown and computes the new schedule; an executing backup must finish first.

Backups stop Minecraft. Players must reconnect after restart. Stopped servers receive no broadcast, and unavailable RCON cannot prevent a backup. Completion is broadcast after readiness. Failed backups attempt to restart a previously running server; if a failure announcement cannot be sent, the panel retries after the server becomes available. Broadcast attempts are persisted before transmission so a panel crash does not replay the same warning; a crash at that boundary can omit a message.

The panel shows the next backup, countdown, stages, elapsed time, verification bytes, archive size and storage/free-space information. It reads each archive entry, validates lengths and checks CRC32 before renaming the temporary archive into a complete ZIP. Retention removes older archives only after a new verified archive exists. Existing download, deletion and restore controls remain available. Safety backups also follow retention.

Jobs retain the prior running state, announcement events and restart errors. An interrupted backup is recovered on startup: unpublished partial files are removed, an already verified archive is checked again, and a previously running server is restarted. Review failures in activity details. Other interrupted file-changing jobs remain failed for review. A successful restore leaves Minecraft stopped.

## Console

The console retrieves timestamped output using a cursor instead of repeatedly replacing a full snapshot. Cursor identity changes on container restart. The display retains at most 2,000 lines or 1 MB, including manual command responses. Very busy logs can exceed the retrieval window; the panel reports that gap. Full server logs stay on disk.

Repeated informational player-list responses collapse by default and can be revealed. Errors, identical ordinary log lines and explicitly displayed command responses remain visible. Background player polling runs every thirty seconds and shares its cache. Pause, clear display, search, auto-scroll and the new-output indicator affect the browser display; they do not erase server logs. Console retrieval stops while paused, while the page is hidden, and when leaving the Console tab.

## API additions

- `PUT /api/servers/:id/backups` continues accepting `backupHours` and `retention`. Optional `backupSchedule` accepts `{mode:"interval"}`, `{mode:"disabled"}` or `{mode:"daily"|"weekly",time:"HH:mm",timezone:"America/Chicago",weekday:0..6}` (Sunday is 0). Omitting it selects the legacy interval mode. Optional `announcements` supplies `enabled`, `warnings` in seconds and the four message templates.
- `POST /api/servers/:id/backups/announce` accepts `{kind:"warning"|"shutdown"|"complete"|"failure",announcements?:...}` and broadcasts a test. This explicitly requested test works even when scheduled announcements are disabled.
- `GET /api/servers/:id/logs` still returns `{text}`. Add `?cursor=start` for `{text,lines,cursor,reset,truncated}`; pass the returned cursor on subsequent requests. Cursors are opaque and reset when the Minecraft container restarts.
- Server snapshots expose `nextBackupAt`. Backup listings expose `verification` and `verifiedAt`. Storage includes `diskFree`. Jobs add stage, start/finish times, processed/total verification bytes, archive metadata, announcement events, prior running state, errors and recovery results.

## Validation

Regression coverage includes countdown persistence/cancellation, offline servers, RCON failures, disk failures, corrupt CRCs, interrupted backups, recovery errors, calendar daylight-saving changes, unchanged duplicate log lines, console limits, hidden/paused tabs, and directory-link escapes. The Linux workflow runs all eight existing Minecraft server types, packaged application checks, and an actual populated v1.2.1 container replacement. No additional hardware platforms are introduced.
